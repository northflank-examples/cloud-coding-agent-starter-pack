# Coding agents compared: how to run each one in the cloud

Fifteen terminal coding agents, compared on the things that matter once you run them on a server instead of your laptop: how to install them, how they authenticate without a browser, how to run them headlessly with prompts off, what they output, and which models they can use. Each agent has its own step-by-step guide.

All values come from each vendor's own documentation, with sources linked in every guide, and are generated from [`data/agents.json`](../data/agents.json). Last checked: **2026-10-19**.

> **Disclosure:** this repository is maintained by [Northflank](https://northflank.com). Northflank Cloud Harness has built-in support for Claude Code, Codex, Cursor, OpenCode, Pi, Devin CLI and OMP; the other agents run in an empty-sandbox harness or anywhere else Linux runs. Each guide also covers running the agent on any VM or container.

## How to choose

- **You want one vendor's best models and tooling:** the vendor's own agent. Claude Code for Claude, Codex for OpenAI models, Gemini CLI for Gemini. Each is tuned for its own models.
- **You want to switch models or providers freely:** an open-source, multi-provider agent. OpenCode, Pi, OMP, goose, Crush, Aider and Qwen Code all work with Anthropic, OpenAI, Google, OpenRouter and local models; you pay the provider directly.
- **You already pay for a tool:** Cursor CLI uses your Cursor plan, Devin CLI your Devin plan, Copilot CLI your GitHub Copilot subscription, Amp and Factory Droid their own plans.
- **You want the smallest possible agent to build on:** Pi has a deliberately small core, no permission system, and RPC and SDK modes for embedding. OMP is a batteries-included fork of Pi, with more built in.
- **You need a server or API to drive it from your own code:** OpenCode (`opencode serve`), Pi and OMP (RPC mode), goose (`goose serve`) and Crush (`crush server`) have one. Claude Code, Codex, Gemini CLI and Copilot CLI have JSON output modes for scripting.

Compare them on your own code: give the same task to several agents in parallel and review the pull requests side by side. See [Running many agents in parallel](../guides/parallel-agents.md#same-task-different-agents).

## Things every agent has in common in the cloud

1. **There's no browser.** Every agent supports an API key or token in an environment variable, and several have a device-code or paste-the-code login for subscriptions. Each guide's *Authenticate without a browser* section lists the options.
2. **Permission prompts have to go.** A headless run can't stop to ask. Every agent has a way to approve actions up front, and some (Pi, OMP, Amp, goose, Crush's `run`) never ask at all. That makes the environment your security boundary: one repository, scoped credentials, a non-root user. See [Security and secrets](../guides/security-and-secrets.md).
3. **They update themselves.** Most agents auto-update by default. Pin versions in images and turn self-updating off for unattended runs; each guide names the setting where one exists.
4. **They read an instructions file.** Most read `AGENTS.md`; Claude Code reads `CLAUDE.md`, Gemini CLI `GEMINI.md`, Qwen Code `QWEN.md`. See [One repository, many agents](../guides/agent-instructions-files.md).
